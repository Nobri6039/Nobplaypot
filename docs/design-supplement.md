# Nobplaypot 新增能力技术补充（v1.2.4）

> 本文补充《作品设计分析》中尚未涵盖的能力：**房客控制权限、浏览器内反向同步、单一权威的界面态、双语界面、全链路诊断**。
> 文中数字均取自当前源码实测（`Nobplaypot.py`）。

## 一、作品设计、发明的目的（补充）

在原有「本地播放 + 局域网同步观看」之外，本轮新增两个设计目的：

1. **从"单向推送"升级为"可授权的协作控制"**。旧模型只有主持发出、房客接收：房客在浏览器里点一下暂停，下一次状态回传就把它推回去，形成两端口令互相踩踏。新设计把"谁有权发起控制"变为房间级、成员级的可授权资源。
2. **从"技术可用"升级为"可交付、可维护"**。新增覆盖全链路的诊断日志、双语界面与统一状态呈现，使非开发者也能复现问题并给出可定位的日志。

## 二、基本思路（补充）

在原有「媒体流推送 + 独立 TCP 命令通道」双通道结构上新增三层：

- **权限层**：主持端为每个已注册客户端维护 `control` 布尔位，默认 `False`（只读）。命令通道入口与网页消息入口设统一闸门。
- **反向感知层**：房客端每 200 ms 采样本地浏览器的 `currentTime / playbackRate / paused`，与「上一帧位置 + 经过时间 × 倍速」的预测值比较，超出阈值即判定为真实用户操作并上报。
- **界面态层**：浏览器同步模式下，主窗口播放类控件统一灰化并拦截交互（含键盘快捷键），保证一次操作只有唯一权威来源。

## 三、创新点（补充）

### 1. "默认只读 + 按需授权"的房间控制权限模型

与"全可控制 / 全锁死"的粗粒度方案不同，本作品把控制权做成**成员级、可随时切换**的开关，与"踢出"同层级放置在成员列表。授权状态随 `welcome` 与 `room` 消息下发，房客端收到 `{"type":"control","allowed":...}` 即时更新界面，无需重连。

拦截范围共 **12 类**客户端指令：

```
seek  rate  play  pause  toggle  seek_rel  seek_ratio
volume  mute  stop  web_cmd  web_url
```

### 2. 基于"预测偏差"的浏览器端操作反演

不依赖页面内 JS 事件注入（会被 CSP、Shadow DOM、播放器自定义协议阻拦），而是**黑盒观测**媒体元素的三个状态量，用运动学预测做差分：

```
Δ = 实测位置 − (上帧位置 + 经过时间 × 倍速)
|Δ| > 1.5 s            → 判为拖动进度
|Δ(playbackRate)| > 0.05 → 判为修改倍速
paused 状态翻转         → 判为暂停 / 继续
```

该方法对任意 HTML5 播放器普适，且能区分"播放自然推进"与"用户干预"。

### 3. 发令冷静期：抑制双端"鬼畜"

站点上报存在 200–500 ms 延迟，若检测器立刻把旧值当成新操作，会形成 `pause → play → pause` 的自我激励。本作品引入：

- `_web_cmd_guard_until`：发出指令后 1.2 s 内不做反向判断，仅刷新基线；
- `_web_ignore_local_until`：收到主持下发状态后 1.0 s 内不回报。

实测可将连续抖动压缩为单条指令。

### 4. "单一权威"的界面态管理

浏览器同步模式下，打开文件、播放/暂停、上一集/下一集、停止、音量、倍速、进度条全部灰化并屏蔽事件（含空格、方向键、滚轮），退出会话时恢复。这不是纯视觉处理，而是把"操作入口唯一化"作为同步正确性的前置条件。

### 5. 可协商的双语界面（含动态文案）

除静态控件外，对**运行时重绘**的文案（Canvas 绘制的连接卡片、缓冲层、拼接串）与**窗口标题、对话框标题**做统一翻译入口。当前 I18N 共 **375 条字面量、285 个去重键**。

### 6. 全链路可观测

为进度同步建立 **19 个阶段**的统一日志标签 `[seek]`：

```
client.drag.start   client.detect      client.send          client.send.dropped
client.local_apply  client.seek_relative client.speed_change client.detect.browser
client.detect.browser_rate client.detect.browser_play       client.apply.rate
client.recv.state   host.recv          host.reject          host.route
host.apply          host.broadcast     ui.slider.press      ui.slider.release
```

任何一次"拖不动"都能在日志上直接判定断点位于哪一段。

## 四、技术关键（补充）

1. **闸门位置**：放在命令通道的**分发入口**（`_apply_remote_command` 与 `web_cmd/web_url` 分支），而非各业务函数内部——新增命令自动受控，避免漏一处即失守。
2. **权限判定以主持端为准**：房客端收到 `control` 只用于界面呈现，"显示为可控制"不等于"本地可放行"。
3. **三重抑制**：发令冷静期、回声抑制窗、差分迟滞阈值叠加，兼顾误报与漏报。
4. **灰化三层实现**：绘制层（禁用色与暗轨道）、控件层（各控件 `set_enabled`）、逻辑层（动作函数入口直接返回并提示）。
5. **同步模式不变量**：主窗口进度条不回写网页进度，网页状态仅作为检测输入与展示来源。

## 五、主要技术指标（补充）

| 指标 | 数值 |
|---|---|
| 控制权限粒度 | 成员级，默认只读 |
| 权限生效时延 | < 1 轮询周期（约 200 ms） |
| 浏览器操作识别时延 | 200–600 ms |
| 拖动识别阈值 | 位置偏差 > 1.5 s |
| 倍速识别阈值 | `playbackRate` 变化 > 0.05 |
| 振荡抑制窗口 | 发令后 1.2 s / 回声 1.0 s |
| 受控指令类型 | 12 类 |
| 界面翻译词条 | 375 条字面量 / 285 个去重键 |
| 诊断日志阶段 | 19 个 |

## 六、与其他方案对比（补充）

| 维度 | 屏幕共享 / 远程桌面 | 流媒体服务器（Plex 等） | Nobplaypot |
|---|---|---|---|
| 传输内容 | 整屏编码 | 转码后媒体 | 1× 直接复用源 ES（无二次压缩） |
| 主持端 CPU | 高（持续编码） | 中（常需转码） | 1× 近似为零 |
| 控制权模型 | 只读观看 | 各自独立 | 成员级可授权协作控制 |
| 部署成本 | 中 | 高（需服务端） | 零（主持端即临时服务端） |
| 页面同步 | 无 | 无 | 浏览器同步（只同步 URL 与进度） |
