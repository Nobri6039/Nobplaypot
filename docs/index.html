FEATURES

不只是播放器，是一间同步放映厅。

局域网同步观影

HOW IT WORKS

三步开一场同步放映。

指令与媒体分开：指令走可靠的 TCP，媒体走低延迟的 UDP；客户端收到的 TS 原包直接交给本机 VLC。

01

主持开场

打开视频，点“主持流式传输”，设置指令端口与媒体端口，输入房间密码，开始主持。

02

房间加入

客户端填入主持的指令地址和媒体地址；如有密码，输入后由主持校验，通过才真正进入房间。

03

实时同步

主持的播放、暂停、拖动、倍速广播给所有人；客户端只发指令，画面由本地 VLC 渲染。

指令通道

TCP · 换行 JSON

心跳、房间状态、密码校验、聊天、成员、播放控制。断线自动重连，离线判定可配置。

→

媒体通道

UDP · TS 原包

1x 时主持端复制源 ES 到 TS，经 UDP 发送；客户端注册后接收原包，交给本机 VLC 负责抖动、乱序与缓冲。

→

本机渲染

VLC · libvlc

画面直接渲染到播放器窗口；全屏、弹幕、缓冲提示都在同一层叠加，不打断解码。

FAQ

常见问题

为什么局域网加入后是黑屏？

最常见的是主持端防火墙没有放行媒体端口。主持端需要允许 TCP 指令端口 和 UDP 媒体端口 的入站；客户端只做出站连接。放行后重新加入即可。

为什么延迟感觉比较大？

延迟主要来自客户端缓冲。默认客户端缓冲是 400ms，可在 设置 → 流式传输 → 客户端缓冲 里调整（200–5000ms）。1x 播放没有编码器，缓冲调小后延迟会明显下降。

为什么有人加入时主持会短暂重连？

VLC 的推流目标在 media 创建时固定，成员变化需要重建 media。重建会自动保留当前进度，不会回到片头；客户端会短暂显示缓冲后继续。

支持公网一起看吗？

支持。在主持端把 TCP 指令端口 和 UDP 媒体端口 映射到公网并放行防火墙，客户端填公网地址即可；客户端仍然只需要出站连接。

1x 播放会改变画质吗？

不会。1x 是流复制，画面就是源文件本身的编码与分辨率。分辨率、码率、帧率这些设置只在变速（非 1x）转码时生效。

需要安装 VLC 或 Python 吗？

使用便携版不需要，运行时已内置。从源码运行则需要 Python 3.10+ 与 64 位 VLC 3.x。
